# ASCII 字符编码

## 存储本质

在 C++ 中，`char` 类型的本质是 **1 字节（8-bit）的整数**。内存中存储的是二进制数值，ASCII 码表则是一张“映射表”，规定了数字与字符的对应关系。

- **双重身份**：它既是字符，也是整数。`char c = 'A';` 等同于 `char c = 65;`。

## 高频字符区间

开发中需熟记的三个关键连续区间：

- **数字 `'0' - '9'`**：码值 **48 - 57**（通过 `c - '0'` 转换为整数）。
- **大写字母 `'A' - 'Z'`**：码值 **65 - 90**。
- **小写字母 `'a' - 'z'`**：码值 **97 - 122**（比大写对位字母多 **32**）。

## 算术逻辑与位运算

利用码值规律可极大简化逻辑：

- **大小写转换**：大、小写字母在二进制第 6 位（权值为 32）正好相反。
  - `c ^ 32`：大小写互换。
  - `c | 32`：强制转小写。
  - `c & ~32`：强制转大写。
- **偏移量计算**：
  - 仅处理小写字母时，使用 `c - 'a'` 将空间压缩至 `0-25`。

## 算法核心：直接寻址表 (Direct Addressing Table)

这是处理字符串类 Hard 题（如最小覆盖子串、异位词）的性能杀手锏。

- **原理**：直接开辟 `int tasks[128]` 数组，将字符码值作为数组下标。
- **优势**：相比 `std::unordered_map`，数组访问是 $O(1)$ 且内存连续，对 CPU 缓存极其友好。

## 符号扩展 (Sign Extension)

C++ 标准未规定 `char` 是否有符号。若字符码值超过 127（如扩展 ASCII 或非法输入），`char` 可能会被解释为负数。

- **风险**：`tasks[s[i]]` 若索引为负，会导致非法内存访问。
- **健壮写法**：使用 `static_cast<unsigned char>(s[i])` 确保索引始终落在 `0-255` 范围内。

## 编码关联

- **UTF-8 兼容性**：UTF-8 编码的前 128 个字符与 ASCII 完全一致。这意味着处理基础英文字符时，所有基于 ASCII 的算术逻辑在现代 UTF-8 环境下依然完全成立。
